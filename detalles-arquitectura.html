Arquitectura Frontend Senior

La arquitectura no consiste en usar más carpetas: consiste en tomar decisiones que permitan que un proyecto crezca sin perder claridad.

Separa por responsabilidades

Una aplicación mantenible distingue entre la interfaz, la lógica del dominio y la comunicación con servicios externos. Esa separación reduce el acoplamiento y facilita las pruebas.

  • UI: componentes que muestran información y gestionan interacción.
  • Dominio: reglas del producto independientes de la interfaz.
  • Infraestructura: peticiones HTTP, almacenamiento y servicios externos.

Organiza por funcionalidades

En lugar de una carpeta global para cada tipo de archivo, agrupa los archivos que cambian juntos dentro de una funcionalidad.

// estructura sugerida
src/
  features/
    cursos/
      CursoCard.tsx
      cursos.service.ts
      cursos.types.ts
  shared/
    ui/
    utils/

Define contratos entre capas

Los tipos e interfaces definen qué datos entra y sale de una funcionalidad. Un contrato estable reduce cambios inesperados en el resto de la aplicación.

type Curso = {
  id: string;
  titulo: string;
  nivel: 'junior' | 'mid' | 'senior';
};

Ubica el estado cerca de quien lo usa

No todo estado necesita ser global. Empieza dentro del componente y compártelo solo cuando varios elementos realmente dependan de él.

  • Estado local para interacción puntual.
  • Estado compartido para datos usados por varias vistas.

Mide antes de optimizar

La arquitectura también cuida el rendimiento, pero las optimizaciones deben responder a una medición real y no a una suposición.

performance.mark('inicio-render');
// Renderiza la interfaz
performance.mark('fin-render');
Idea clave

La mejor estructura es la que hace fácil encontrar, cambiar y eliminar código. Empieza simple y extrae capas cuando el problema lo justifique.
